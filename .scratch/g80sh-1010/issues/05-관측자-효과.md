# 05 — 측정이 증상을 억제하는가 (관측자 효과)

Type: task
Status: open
Blocked by: —

## Question

ETW 캡처나 감시 도구가 EDID 재생성·재열거를 **억제**해서 증상이 안 나는 것 아닌가.
사실이라면 "잡으려 들면 사라지는" 구조가 되어, 지금 설계로는 영원히 못 잡는다.

기전상 완전히 배제할 수는 없다. ETW provider를 켜면 드라이버 코드 경로와 타이밍이
바뀔 수 있고, `Kernel-PnP` verbose는 실측 273건/초의 부하가 있다.
(`Dxgkrnl_StatusChangeNotify`는 0건/초라 사실상 수동적이다.)

## 09-19 실험 A·B에 대해서는 기각됨

두 음성 결과는 **ETW 세션이 하나도 떠 있지 않은 상태**에서 나왔다.

```
16:41:08  auto rev.1 armed        ← rev.1 은 트리거가 걸려야 세션을 만든다
                                     트리거 없었음 (auto.log 에 capture start 없음)
16:45:19  실험 A 강제 끄기   → 0건    세션 없음
16:53:20  실험 B 자연 절전   → 0건    세션 없음
16:54:48  session running (circular 512MB)   ← 세션은 여기서 처음 떴다
```

폭풍의 종료도 설명된다: 마지막 1010은 **16:31:25**, 화면이 켜진 것이 **16:30:33**이다.
이 세션의 첫 명령은 16:34경이었으므로 폭풍의 종료에 측정이 관여할 여지가 없다.

곁가지 교란 하나는 기록해 둔다: 실험 B 직전 16:52:17에 `powercfg /setactive SCHEME_CURRENT`가
실행됐다(전원 계획 재적용). 실험 A에는 없었으므로 두 음성을 함께 설명하지 못하지만,
실험 B 단독으로는 교란 변수다.

## 남은 검증 — 앞으로에 대해서는 열려 있다

09-08 이후 4,100건 이상이 **세션이 한 번도 뜨지 않은 상태**에서 기록됐다.
16:54:48부터 순환 버퍼 세션이 상시 가동이므로 판정이 가능하다.

- **세션이 떠 있는데 폭풍이 나면** → 관측자 효과 기각. 캡처가 바로 원자료가 된다.
- **16:54:48 이후 폭풍이 완전히 끊기면** → 의심 성립. 이때 검증법:
  세션을 끈 구간과 켠 구간을 번갈아 두고(예: 2시간 단위) 발생률을 비교한다.
  단 (3)"저녁에 잦아드는 시간대"와 뒤섞이므로, **부팅 후 첫 절전**처럼 폭풍 확률이
  높은 구간에서 켬/끔을 번갈아야 한다.

## 판정에 필요한 기록

`auto.log`의 `session running` / `auto stopped` 시각과 1010 발생 구간을 겹쳐 본다.
감시자가 세션 상태를 로그에 남기고 있으므로 사후 대조가 가능하다.

## 09-18 분에 대해서도 기각 — 캡처는 존재한 적이 없다

"어제 재부팅까지 했는데 캡처가 도는 동안 증상이 없었다"는 관찰의 전제가 성립하지 않는다.
09-19 16:40 이전에 ETW 캡처가 실행된 흔적이 **하나도 없다.**

```
디스크 전체 .etl 중 G80SH 것    :  g80sh-live.etl 하나뿐, 09-19 16:54:48 생성
_evidence\auto.log 생성 시각     :  2026-09-19 16:40:36
g80sh-dxg* 산출물                :  0건
Kernel-EventTracing 09-18 G80SH  :  0건
tools\g80sh-etw-capture.ps1      :  없음 (C:\dev, C:\Users\hans1 전체 검색 0건)
tools\g80sh-etw-auto.ps1         :  없음
작업 'G80SH ETW Auto'            :  등록 안 됨
```

`추가분석.md` 9항의 "09-18 18:39 무장, 최대 20시간 대기"는 기록만 남고 실물이 없었다.
재부팅 뒤에도 돌 것이 없었다 — 등록된 작업이 없으면 뜰 수 없다.

**순서도 반대다:**

```
09-18 17:36:13  마지막 1010   ← 증상이 먼저 멎었다
09-18 18:39     "무장"         ← 한 시간 뒤
```

증상이 멎은 뒤에 장치를 걸었다고 기록한 것이지, 캡처가 증상을 누른 것이 아니다.

## 반대 증거 — 수동 감시는 폭풍과 공존했다

`g80sh-evidence.ps1`(Get-WinEvent 집계기)은 실제로 돌았고 폭풍과 정면으로 겹쳤다.

```
2026-09-18 13:12:41  12:57-13:12  G80SH=18  interval=48s  screen=off
2026-09-18 13:27:41  13:12-13:27  G80SH=18  interval=47s  screen=off
2026-09-18 14:27:41  14:12-14:27  G80SH=20  interval=45s  screen=off
```

단 이것은 이벤트 로그 폴링이라 ETW provider를 켜는 것과 부하 성격이 다르다.
따라서 **ETW에 대한 의심은 앞으로에 대해 계속 열어 둔다** (위 "남은 검증" 참조).
