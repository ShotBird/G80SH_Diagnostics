
드라이버 버전은 동일(`32.0.31041.1004`). 즉 **바뀐 것은 저장값 제거 하나뿐**이다.
실험 조건으로 깨끗하다.

## 결과 2 — 유령 devnode 는 남았고, 오히려 늘었다

```
Default_Monitor
   7&16b8ddb4&0&UID256   EDID 없음    ← 그대로
   1&1f0c3c2f&0&UID256   EDID 없음
   1&31c5ecd4&0&UID256   EDID 없음
SAM7B0C
   7&16b8ddb4&0&UID256   EDID 384B    ← 정상
   1&8713bca&0&UID0      EDID 128B    ← 재설치 중 신규
```

예상대로다. 유령은 EDID 읽기가 실패할 때마다 재생성되는 **증상의 부산물**이지 원인이 아니다.
`DEFAULT_MONITOR\7&16b8ddb4&0&UID256` 과 `SAM7B0C\7&16b8ddb4&0&UID256` 은
**인스턴스 ID가 같다** — 같은 포트의 두 신원일 뿐 서로 막는 관계가 아니다.

**부수 관측**: 신규 유령의 EDID 가 **128바이트**다. 정상은 384바이트(base + 확장 2블록).
재설치 중 base 블록만 읽히고 확장 블록을 못 읽은 순간이 있었다는 뜻이다.
DSC·HDR 정보가 확장 블록에 있다. **EDID 읽기가 블록 단위로도 불안정하다.**

→ **누적 절전 60분 무사고**를 판정 기준으로 잡고 장시간 감시 중.
   3건 이상 나오면 즉시 "재발"로 끊는다. 로그: `_evidence\postddu-long.log`

## 판정이 나오면

- **멎음** → 잔재가 원인. (c) 근원개선이 PC 쪽에서 성립한다.
  09-08 설치 당시 인식 실패가 드라이버에 남긴 오염이 뿌리였다는 뜻.
- **재발** → 잔재는 원인이 아니다. **PC 쪽 후보가 소진된다.**
  ①(모니터 펌웨어)만 남고, 근원개선의 실행 주체가 삼성으로 넘어간다.
  → 맵의 도착지를 다시 잡아야 한다. 범위 밖이던 (b) 제출 트랙이 유일한 경로가 된다.
  → 그 경우 **"PC에서 할 수 있는 건 다 해봤다"가 로그로 증명된 상태**가 되어
     제출 근거로서는 오히려 강해진다. [[삼성제출_대장]]

누적 절전 19분 무사고 뒤 20분 36초 지점에서 시작했다. 간격 46초는 기존 통계
(평균 48.5초, 하한 37초)와 완전히 일치한다. **같은 현상이다.**

### 발생 지연이 길어진 것은 근거로 못 쓴다

```
부팅 11:40 → 첫 절전 12:26 →    47초 만에 폭풍   (조치 없음)
부팅 17:18 → 첫 절전 17:41 →   222초 만에 폭풍   (조치 없음)
부팅 18:52 → 첫 절전 19:05 → 1,236초 만에 폭풍   (재설치 후)
```

길어지는 추세로 보이지만 **저녁에 잦아드는 오늘의 패턴과 구분되지 않는다.**
09-18도 17:36에 멎었고, 09-19도 16:31에 멎었다. 시간대가 교란 변수라 재설치 효과로
귀속할 수 없다. 재설치 전후를 같은 시간대에 비교해야 하는데 그건 불가능하다.

### 결론

**드라이버가 들고 있던 이전 모니터 EDID 잔재는 원인이 아니다.**
드라이버를 완전히 재설치하고 `EDID_331_2701` ×2 와 `freesync_v1` 저장값을 모두 지웠는데도
같은 파형이 돌아왔다.

### 도착지에 주는 영향

**PC 쪽 후보가 사실상 소진됐다.**

| 후보 | 결과 |
|---|---|
| `EDID_OVERRIDE` 확장 | 보고서 9-1 — 원리상 불가 (열거 후 적용) |
| ② AMD EDID 에뮬레이션 | 06 — ADL 쓰기 `-8`, GUI 항목 없음. 실행 불가 |
| 드라이버 잔재 제거 | **08 — 제거했으나 재발** |
| 유령 devnode 제거 | 남음. 효과 기대는 낮으나 비용이 싸다 → 09 |
| ① 모니터 펌웨어 | PC 에서 불가. 삼성 영역 |

09(유령 devnode 제거)까지 하고 나면 (c) 근원개선을 PC 쪽에서 더 시도할 것이 없다.
그 시점에 **맵의 도착지를 다시 잡아야 한다.**

### 제출 근거로는 오히려 강해졌다

"PC 에서 할 수 있는 조치를 전수로 시도했고 전부 실패했다"가 로그로 남았다.
드라이버 완전 재설치까지 했는데도 지속된다는 사실은 삼성 측이 PC 쪽으로 돌릴 여지를
크게 줄인다. [[삼성제출_대장]] 에 반영할 것.
