## 09-1 유령 devnode 제거

```
제거 전: DISPLAY\DEFAULT_MONITOR\7&16B8DDB4&0&UID256  (Present=False)
         DISPLAY\SAM7B0C\1&8713BCA&0&UID0             (Present=False, EDID 128B)
19:49:42  pnputil /remove-device 둘 다 rc=0
19:53:07.851  SAM7B0C
19:53:48.801  SAM7B0C   (41초)
19:54:38.216  SAM7B0C   (50초)
```

예상대로 기각. 유령은 EDID 읽기 실패 때마다 재생성되는 **부산물**이지 원인이 아니다.
`DEFAULT_MONITOR\7&16b8ddb4&0&UID256` 과 `SAM7B0C\7&16b8ddb4&0&UID256` 은 인스턴스 ID가
같다 — 같은 포트의 두 신원일 뿐 서로 막지 않는다.

## 09-2 OSD 공장 초기화

모니터 OSD 에서 공장 초기화 실행. **EDID 가 바이트 단위로 동일하다.**

```
초기화 전  SAM7B0C len=384 head=00ffffffffffff004c2d0c7b433233311f240104
초기화 후  SAM7B0C len=384 head=00ffffffffffff004c2d0c7b433233311f240104
```

초기화로 모니터가 내주는 EDID 는 달라지지 않는다. 폭풍도 그대로 이어졌다.

## 09-3 주사율 240Hz → 60Hz

`3840x2160@240Hz` 는 DP 1.4 대역폭상 DSC 필수. 60Hz 로 내리면 DSC 가 빠진다.
"EDID 확장 블록을 못 읽는다"와 DSC 가 같은 축인지 가리려는 실험.

**1차 시도는 무효였다.** 적용(19:59:45) 1분 전인 19:58:45 에 사용자가 화면을 켜서
폭풍이 이미 멎어 있었다. 대조군 소실을 모른 채 적용했다.

```
19:14:13  화면 꺼짐
19:41:03 ~ 19:57:13   폭풍 19건
19:58:45  화면 켜짐 ← 대조군 소실
19:59:45  60Hz 적용
20:00:54  화면 꺼짐
20:00:54 ~ 20:14:38   60Hz   828초  → 0건
20:14:38 ~ 20:33:10   240Hz 1,112초 → 0건, 이후 재발
```

**다만 결과적으로 기각 판정이 가능하다.** 60Hz 가 효과였다면 240Hz 복귀 직후 재발했어야
하는데 **18.5분을 더 버텼다.** 두 구간 다 침묵했고 240Hz 쪽이 더 길었다.
주사율/DSC 는 방아쇠가 아니다.

도구: `tools\g80sh-hz.ps1` (`\\.\DISPLAYn` 번호가 재열거로 계속 바뀌므로 모니터 ID 로 찾는다)

## 부수 발견 — 발현 지연이 저녁으로 갈수록 길어지고, 화면을 켜면 리셋된다

실험 관점에서도 중요하다 — **판정 1회 비용이 낮에는 1분, 밤에는 30분 이상**이다.
남은 변수는 낮에 시험해야 한다.
