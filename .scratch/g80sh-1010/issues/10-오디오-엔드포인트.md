```

엔드포인트 이름은 `1 - Odyssey G80SH(AMD High Definition Audio Device)`.
**모니터 스피커가 붙었다 떨어졌다를 반복하고 있었다.**

## 왜 중요한가 — EDID 확장 블록의 직접 지표다

```
EDID 384바이트 = base 블록 128 + 확장 블록 2개 (256)
오디오 정보(Short Audio Descriptor)는 확장 블록(CTA-861)에 있다
```

DP 오디오 엔드포인트는 확장 블록에서 파생된다. 따라서 **엔드포인트가 생겼다 사라지는 것은
확장 블록이 읽혔다 안 읽혔다 한다는 직접 증거**다.

08 에서 본 **128바이트 EDID 유령**(`SAM7B0C\1&8713bca&0&UID0`, base 만 있고 확장 없음)과
정확히 같은 축이다.

**그리고 이것이 사용자가 겪던 "장치 연결/해제음이 계속 난다"의 정체다.**
모니터 devnode 만 흔들리는 것이 아니라 오디오 엔드포인트가 같이 붙었다 떨어지며 소리를 낸다.

## 부수 확인 — FreeSync 가 EDID 프로파일을 바꾼다

09-4 에서 OSD 로 FreeSync 를 끄자 EDID 제품 코드가 바뀌었다.

```
FreeSync ON    SAM 0x7B0C  →  DISPLAY\SAM7B0C\7&16B8DDB4&0&UID256
FreeSync OFF   SAM 0x7B0B  →  DISPLAY\SAM7B0B\7&16B8DDB4&0&UID256  (새 devnode)
```

**보고서 8항 「EDID 프로파일 이중화」의 실체가 이것이다.** 다만 보고서가 "대기 상태 EDID"로
본 것은 틀렸고, 실제 스위치는 **VRR 상태**다.

그리고 폭풍 중 두 가지가 모두 관측됐다:

```
프로파일 간 전환   21:08:41 SAM7B0B → 21:09:13 SAM7B0C → 21:09:40 SAM7B0B  (교대 제거)
프로파일 내 반복   20:53~20:58  SAM7B0B 만 반복 제거 (FreeSync OFF 고정 상태)
```

→ **전환이 원인의 전부가 아니다.** 어느 프로파일에 고정해도 같은 주기로 제거된다.

건드리지 않았다. 실사용 출력은 `스피커(Realtek(R) Audio)`라 영향 없다.
**모니터 스피커는 기능 자체가 막혀 있어 잃는 것도 없다**(사용자 확인).

**이것은 우회책이다** — 소리를 없앨 뿐 1010 반복을 고치지 않는다(맵 Notes 상시규칙 1).

## 기전 정리 (10 이 더한 것)

```
모니터가 절전 중 EDID 확장 블록을 안정적으로 내주지 못한다
  → 오디오 엔드포인트 생성/제거 반복      (소리의 원인)
  → 모니터 devnode 제거 반복 = 1010      (폭풍)

  → Kernel-PnP 220 (GPU 자식 재조회) → 1010
```

## Answer — 기각. 오디오는 부산물이지 인과 고리가 아니다 (2026-09-20 17:00)

**09-20 14:33~14:40 에 폭풍이 기준선 속도 그대로 재발했다.** GPU 오디오는 그때도 꺼져 있었다.

### 오디오가 정말 꺼져 있었는지 — 확인함 (상시규칙 2)

```
HDAUDIO\...REV_100A\7&4A72B29&0&0001   Status = Error   ← 재부팅 후에도 유지
HDAUDIO\...REV_1008\5&28A47E64&0&0001  Status = OK      ← 내장, 건드리지 않음

그리고 오늘 캡처(`g80sh-dxg-agg-0920-1434-1.txt`, 14:31:35~14:36:21)에
**`MMDEVAPI`/`audioendpoint`/`HDAUDIO` 문자열이 한 건도 없다.** 오디오 엔드포인트가
아예 존재하지 않는 상태에서 폭풍이 온전히 돌았다.

### 파형이 동일하다 — 02 의 결론 그대로

```
provider/id 분포   DxgKrnl 10011  1307 / Kernel-PnP 222 123 / 220 123 / 808 11 / 1010 7

#3  -41ms  220  PCI\VEN_1002&DEV_7550...  →  0ms 222 → 0ms 1010 SAM7B0C
#4  -62ms  220  PCI\VEN_1002&DEV_7550...  →  0ms 222 → 0ms 1010 SAM7B0C
#5  -38ms  220  PCI\VEN_1002&DEV_7550...  →  0ms 222 → 0ms 1010 SAM7B0C
```

02 가 잡은 **-42ms** 와 같다. 220 보다 앞선 10011 은 여전히 0건.
`Default_Monitor` 로의 강등(#3 +141ms)과 `808 End device add` 도 그대로 재현됐다.

주기도 그대로다: **46.9 / 39.8 / 40.0 / 43.0초.**

### 따라서

**오디오 엔드포인트의 진동은 확장 블록 불안정의 *지표*이지, 재열거를 만드는 고리가 아니다.**
엔드포인트를 통째로 없애도 220→1010 사이클은 같은 주기·같은 파형으로 돈다.

10 이 세운 기전 해석("확장 블록을 안정적으로 못 내준다")은 **유지된다.**
부정되는 것은 인과 방향 — 오디오는 원인 쪽이 아니라 결과 쪽이다.

**09-19 21:11 삼성 디스플레이 앱 초기화도 같이 기각된다.** 교란 변수였지만 재발로 둘 다 무효가
됐으므로 가릴 필요가 없어졌다.
