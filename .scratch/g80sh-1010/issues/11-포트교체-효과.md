포트 교체가 실제로 한 일:

```
DP 링크 재훈련 (레인 수·링크 레이트 재협상)

**결정적 대조**: 08 에서 드라이버를 완전 재설치해 DAL 저장값(`EDID_331_2701` 등)을 전부
지웠는데 **즉시 재발**했다. 반면 포트 교체는 **사흘**을 벌었다.

→ **PC 쪽 저장값 초기화로는 안 되고, 물리 링크를 새로 세워야 효과가 있다.**
→ **초기화되는 것은 모니터 쪽 상태이며, 그 상태가 며칠에 걸쳐 다시 나빠진다.**

이 해석은 오늘 확인한 다른 것들과 전부 일관된다:
절전 중 EDID 확장 블록 불안정(10), 발현 지연이 날마다 다른 것(09), 09-10~12 정지.

## EDID 프로파일이 셋이다

```
0x7B0C   정상 (FreeSync ON)              — 대부분
0x7B0B   FreeSync OFF                    — 09-19 OSD 스위치로 재현 확인
0x7B11   09-09 22:18:42 단 한 번, 18초   — 포트 교체로 링크를 새로 세우는 순간
```

`SAM7B11` 은 Configuration 400/410 으로 정식 구성까지 됐다가 18초 뒤 제거됐다.
~~**링크 재수립 순간에만 나타나는 세 번째 프로파일**이다.~~

> **2026-09-20 19:31 정체 확인 ([15](15-dp11-저대역폭.md)).**
> OSD 에서 **DisplayPort 버전을 1.1 로 낮추자 `SAM7B11` 이 지속 프로파일로 붙었다.**
> → `7B11` 은 "재수립 순간"의 프로파일이 아니라 **「저대역폭 링크」 프로파일**이다.
> 09-09 포트 교체 때는 링크 재협상 중 일시적으로 저속으로 떨어졌고, 그 18초 동안
> 모니터가 이 EDID 를 내준 것이다.
>
> 프로파일 지도: `7B0C` = FreeSync 동작·정상 대역폭 / `7B0B` = FreeSync 해제 /
> `7B11` = 저대역폭. **스위치는 VRR 상태와 링크 대역폭 두 축이다.**
