# 15 — DisplayPort 를 1.1 로 낮추면 멎는가

Type: task
Status: claimed
Blocked by: —

## Question

OSD **시스템 > DisplayPort 버전**을 **1.1** 로 낮춘 상태에서 1010 반복이 멎는가.

링크 계층을 가장 크게 바꾸는 조치다. 지금까지 시도한 것 중 **PC·모니터 사이 전송 구성을
가장 많이 바꾼 시험**이다.

## ★ 먼저 — 세 번째 EDID 프로파일 `SAM7B11` 의 정체가 밝혀졌다

11 이 남긴 수수께끼가 여기서 풀렸다.

```
11 의 기록
  0x7B11   09-09 22:18:42 단 한 번, 18초   — 포트 교체로 링크를 새로 세우는 순간
           "링크 재수립 순간에만 나타나는 세 번째 프로파일"
```

**DP 를 1.1 로 낮추자 `SAM7B11` 이 지속 프로파일로 붙었다.**

```
19:31:53 확인
  DISPLAY\SAM7B11\7&16B8DDB4&0&UID260   present OK
  모드  3840x2160 @30Hz
```

→ **`7B11` 은 "링크 재수립 순간"의 프로파일이 아니라 「저대역폭 링크」 프로파일이다.**
09-09 포트 교체 때는 링크가 재협상되며 일시적으로 저속으로 떨어졌고, 그 18초 동안
모니터가 이 EDID 를 내준 것이다.

### 프로파일 지도 완성

```
0x7B0C   FreeSync 동작, 정상 대역폭          ← 평소
0x7B0B   FreeSync 해제                       ← 09-4 OSD 스위치로 재현
0x7B11   저대역폭 링크 (DP 1.1)              ← 이번에 확정
```

보고서 8항의 「EDID 프로파일 이중화」는 **이중화가 아니라 삼중화**이고,
스위치는 **VRR 상태와 링크 대역폭** 두 축이다.

## 실행 기록 — 2026-09-20 19:30 경

```
19:26:46  화면 꺼짐 (DSC 끄기 시험 구간)
19:27:22 ~ 19:29:23   폭풍 6건, 시간당 122.6      ← 직전 기준선. 활발
19:30:21  사용자가 화면 켜서 OSD 조작
19:30:37  SAM7B0C 1010    ┐ DP 버전 전환에 따른
19:31:09  SAM7B0C 1010    ┘ 링크 재협상 / 프로파일 전환
19:31:53  상태 확인 — SAM7B11 로 안착
```

### 전환 후 상태

```
G80SH   DISPLAY\SAM7B11\...UID260   3840x2160 @30Hz    ← 240Hz → 30Hz
G50F    DISPLAY\SAM79DF\...UID256   2560x1440 @165Hz
동글    DISPLAY\BBC0104\...UID265   3840x2160 @59Hz
```

## ⚠ 이번 시험은 변수가 여럿이다 (상시규칙 4 위반)

DP 버전을 낮추면 딸려 오는 것이 많다.

```
DisplayPort 버전   2.1 → 1.1        HBR 링크, 레인 구성·클럭 전부 다름
FreeSync           자동 비활성      설명서 p47: "DP 버전이 1.1인 경우 FreeSync 비활성"
DSC                이미 꺼진 상태   14 에서 껐고 안 되돌림
EDID 프로파일      7B0C → 7B11      모니터가 다른 EDID 를 내준다
주사율             240Hz → 30Hz
```

**단일 변수 시험이 아니라 "링크 구성을 최대한 다르게 만든" 산탄총 시험이다.**

그래도 값어치가 있다 — **여기서도 터지면 링크 계층 전체가 죽는다.**
멎으면 그때 변수를 쪼개면 된다(어느 것이 효과인지는 그다음 문제).

곁다리 변수 중 FreeSync 는 이미 단독으로 기각됐고(09-4), DSC 도 단독 기각됐다(14).
**남는 진짜 새 변수는 「링크 대역폭/DP 버전」과 「7B11 EDID」 둘이다.**

## 판정 기준

```
터진다         → 즉시 기각. 링크 계층 전체 소진. 모니터 확정이 더 굳어진다
30분 이상 조용 → 의미 있음. 다만 확정 아님 (상시규칙 3, 45% 함정)
                 이 경우 변수를 쪼개야 한다: DP 1.2 → 1.4 → 2.1 로 올리며 어디서 재발하는지
```

직전 기준선이 강하다 — 19:27~19:29 에 시간당 122.6 으로 돌고 있었다.

## 되돌리기

```
OSD → 시스템 → DisplayPort 버전 → 2.1
OSD → 시스템 → DisplayPort DSC → 사용
```

**DP 1.1 은 실사용 불가다** — 4K 30Hz 다. 시험이 끝나면 반드시 되돌려야 한다.

## 제출에 미치는 영향

제출 진술은 이미 **"제품이 광고하는 사양(DP 2.1 / 4K 240Hz) 그대로 쓰는데 발생한다.
사양대로 못 쓰게 하는 조치는 해결이 아니다"** 로 서 있다.

- 여기서도 터지면 → 배제 목록에 한 줄 추가. 진술 그대로
- 여기서 멎으면 → **"DP 1.1(4K 30Hz)로 낮추면 멎지만 그것은 제품을 쓸 수 없게 만드는
  조치다"** 가 된다. 이것도 제출에 유리하다 — 모니터 쪽 링크 처리 문제임을 가리킨다
