## Decisions so far

- **도착지 확정**: (a) 원인 확정 + (c) 근원개선. (b) 삼성 제출은 범위 밖, 기록만.
- [01 — ETW 캡처 확보](issues/01-etw-캡처-확보.md): 09-18에 "구성했다"던 측정 장치가 실재하지
  않아 처음부터 다시 만들었다. **rev.2는 순환 버퍼(512MB)를 상시 돌리고 트리거 때 덤프**한다 —
  트리거 후에 세션을 켜면 방아쇠가 끄는 순간에 있을 때 매번 놓친다. 09-19에 폭풍 4회 포착.
- [02 — 48초 타이머의 주인](issues/02-선후-판정.md) **★ 핵심 결정**:
  **OS/드라이버가 먼저 조회를 건다.** 폭풍 사이클은 `Kernel-PnP 220`(GPU 자식 재조회)이
  앞서고 `DxgKrnl` StatusChangeNotify는 그 뒤에 온다. **220보다 앞선 10011은 0건**.
  정상 전환 기준선은 정반대(10011이 20여 건 선행). 재설치 후에도 -42ms로 동일 재현.
  → 모니터가 링크를 끊어 알린 것이 아니다. AMD miniport가 스스로
  `IoInvalidateDeviceRelations`를 걸었다.
- [03 — 발생 조건 재확정](issues/03-발생조건-재확정.md):
  **원격 접속은 조건이 아니다**(보고서 4-3 폐기) — 원격 없이 4시간 406건.
  **끄기 명령의 경로도 방아쇠가 아니다** — 강제 339초 0건, 자연 560초 0건.
  **`Kernel-Power 566`이 화면 전원 전환의 OS 정식 기록**임을 발견(08-08부터 보존).
  폭풍은 566 꺼짐 구간과 정확히 겹치고, **강제 끄기는 566을 남기지 않는다**.
  단 566 꺼짐은 **필요조건이지 충분조건이 아니다**.
- [04 — AMD EDID 에뮬레이션이 실재하는가](issues/04-amd-edid-에뮬레이션.md):
  기능은 실재하고 계층상 `EDID_OVERRIDE`보다 상류다. **다만 가용성 판정은 틀렸다** —
  `EDIDManagement_Caps`가 `supported=1`을 돌려주지만 쓰기 경로는 Pro 전용이다(06이 정정).
  DSC는 제약이 아니다. AMD 릴리스 노트의 "EDID 에뮬레이션 + MSB 복귀 blank-out" 경고 확인.
- [05 — 관측자 효과](issues/05-관측자-효과.md): **기각.** 09-19 16:40 이전에 ETW 캡처가
  실행된 흔적이 하나도 없다. "캡처와 증상이 공존한 적 없다"는 이유는 억제가 아니라 **부재**다.
  09-18의 "무장"은 마지막 1010보다 1시간 뒤였다. 수동 집계기는 폭풍과 정면으로 공존했다.
- [06 — AMD EDID 에뮬레이션 검증 실험](issues/06-에뮬레이션-검증실험.md): **② 실행 불가 확정.**
  `ConnectionData_Set`·`EmulationMode_Set` 전 변형이 `-8 ADL_ERR_NOT_SUPPORTED`,
  AMD Software GUI 에도 항목 없음. 04의 가용성 근거를 정정한다.
- [07 — 증상은 설치 당일부터다](issues/07-증상-시작-시점.md) **★ 제출 핵심**:

  존재한다. 메인보드에 영상 출력이 있으면 **장비 없이** AMD 외장 드라이버/miniport 를
