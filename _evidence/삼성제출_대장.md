## 7. 【중대】 09-19 17:45 폭풍 캡처 — 제출 전략에 영향을 준다

폭풍 구간의 ETW 원자료를 확보했다. **결과가 삼성에 유리한 쪽이다. 반드시 감안할 것.**

원본: `g80sh-dxg-0919-1745-1.etl` (13,238,272 bytes, 115,296건)
디코드: `g80sh-dxg-agg-0919-1745-1.txt`, `g80sh-dxg-0919-1745-1.csv`

### 폭풍 사이클의 선후

```
  -42ms   Kernel-PnP 220   Begin querying bus relations
                           for device PCI\VEN_1002&DEV_7550...   ← GPU. 여기서 시작
   -1ms   DxgKrnl 10011    StatusChangeNotify  ← 220 이후에야
    0ms   Kernel-PnP 1010  DISPLAY\SAM7B0C 제거
```

두 폭풍 사이클 모두 **220보다 앞선 `DxgKrnl` 10011이 0건**이다.
정상 전환(17:08:52)에서는 10011이 20여 건 앞섰다. **정반대다.**

### 무엇을 뜻하는가

- 재열거를 개시한 주체는 **PC 쪽(AMD display miniport)**이다.
  `IoInvalidateDeviceRelations`를 드라이버가 스스로 걸었다.
- **모니터가 링크를 끊어 OS에 알린 것이 아니다.** 그 경우라면 정상 전환처럼
  `StatusChangeNotify`가 앞섰어야 한다.

### 제출에 어떤 영향인가 — 솔직하게

**이것은 "모니터 불량"이라는 진술을 약화시킨다.** 삼성 측이 "PC 그래픽 드라이버 문제"로
돌릴 근거가 된다. 숨기면 나중에 더 크게 깨진다.

다만 아직 삼성에 유리하다고 단정할 수도 없다:

1. 캡처는 **드라이버가 왜 그렇게 판단했는지**를 말해주지 않는다. 드라이버가 주기적으로
   링크/EDID를 읽다가 실패해 "자식이 사라졌다"고 결론 냈다면 뿌리는 여전히 모니터다.
2. `Default_Monitor`(EDID 읽기 실패) 1,294건이 이를 뒷받침하는 정황이다.
3. **G50F(`SAM79DF`)는 같은 GPU·같은 드라이버·같은 절전에서 131건뿐**이다.
   드라이버 일반의 문제라면 두 모니터가 비슷해야 한다.
4. 기존 보고서 5항의 "증상이 포트가 아니라 모니터를 따라 이동" 관찰이 그대로 유효하다.

**→ 제출 진술은 "모니터가 링크를 끊는다"가 아니라
   "이 모니터에서만 드라이버가 반복적으로 장치 소실로 판단한다"로 가야 한다.**
   전자는 이 캡처가 반증한다. 후자는 캡처와 모순되지 않고 대조군(G50F)이 뒷받침한다.

### 06 검증 실험이 이 항목을 확정하거나 뒤집는다

AMD EDID 에뮬레이션을 켰을 때 폭풍이 멎으면 "드라이버가 EDID를 못 읽어서 생기는 일"이
확정되고, 그러면 **모니터가 EDID를 제대로 내주지 않는다**는 진술이 성립한다.
멎지 않으면 다른 축을 찾아야 한다. **확정 전까지 이 항목을 제출 문서에 반영하지 말 것.**

## 10. 【최중요】 설치 당일부터 정상 동작한 적이 없다 — 초기 불량

09-19 확인. **제출 진술의 골격을 바꾼다.**

### 사실

- **2026-09-08이 G80SH를 새로 설치한 날이다.** 사용자 확인:
  "모니터를 새로 설치한 날인데, 설치했을 때 모니터가 인식이 바로 안 되었던 문제가 있었어.
   어떻게 다시 연결 성공했는지는 기억이 안 나."
- Kernel-PnP 로그는 **2026-08-08까지** 보존돼 있어 설치 이전을 확인할 수 있다.

```
08-08 ~ 09-07 (한 달)   SAM7B0C 1010 :  0건   ← 모니터 연결 전
09-08 21:59:49          SAM7B0C 첫 1010       ← 설치 당일
09-08 ~ 09-19 (11일)    SAM7B0C 1010 : 3,088건
```

- 그 한 달의 DISPLAY 1010 143건은 전부 다른 장치다(`SAM79DF` 대부분, `LHC2701`,
  `Default_Monitor` 2건). `LHC2701`은 G80SH 이전에 쓰던 모니터로 보인다.
- 설치 당일 비정상 종료 2회(`Kernel-Power 41`, 20:36:29 / 21:28:45, BugcheckCode=0).
  BSOD가 아니라 강제 전원 차단 또는 행. **인식 불량과 씨름한 정황과 일치한다.**

### 제출 진술은 이렇게 간다

> **설치 당일부터 한 번도 정상 동작한 적이 없다.**
> 설치 시점에 인식 불량이 있었고, 그 이후 11일간 장치 제거가 4,500회 이상 반복됐다.
> 같은 PC · 같은 그래픽카드 · 같은 드라이버에 연결된 다른 모니터(Odyssey G50F)는
> 같은 기간 131건뿐이다. 발생은 화면이 절전에 들어가 있는 동안에만 일어난다.

**"멀쩡하다 고장났다"가 아니라 「초기 불량」이다.** 교환 사유로 훨씬 명확하다.

## 12. 09-19 야간 — 소프트웨어 계층 전수 배제 완료

### 12-1. 펌웨어가 최신인데도 발생한다 【중요】

```
OSD 정보 메뉴 : M-H800GGAA-1002.2   (최신 버전)
```

삼성 측의 두 가지 상투적 대응을 미리 차단한다:

- "펌웨어를 업데이트하세요" → **이미 최신**
- "구버전의 알려진 문제입니다" → **최신에서 발생**

### 12-2. 배제된 조치 전수 목록

| 계층 | 조치 | 결과 |
|---|---|---|
| Windows | `EDID_OVERRIDE` | 원리상 불가 (열거 후 적용) |
| AMD 드라이버 | EDID 에뮬레이션 | 실행 불가 (ADL 쓰기 전부 `-8`, GUI 항목 없음) |
| AMD 드라이버 | **완전 재설치 (Factory Reset)** | **무효** — 파형까지 동일(-42ms) |
| AMD 드라이버 | 이전 모니터 EDID 잔재 제거 | 무효 |
| Windows PnP | 유령 devnode 제거 | 무효 |
| 모니터 설정 | **OSD 공장 초기화** | **무효** — EDID 바이트 무변화 |
| 모니터 설정 | 삼성 디스플레이 앱 설정 초기화 | 무효 |
| 링크 | 주사율 240→60Hz (DSC 회피) | 무효 |
| 링크 | **FreeSync / VRR 끄기** | **무효** — 11분 15건, 파형 무변화 |
| 모니터 펌웨어 | 최신 `M-H800GGAA-1002.2` | **최신에서 발생** |

**소프트웨어·설정 계층이 전부 배제됐다. 남는 것은 하드웨어다.**

### 12-3. 사용자가 겪는 "장치 연결/해제음"의 정체를 규명했다

모니터 스피커(DP 오디오 엔드포인트)가 붙었다 떨어졌다를 반복한다.

```
20:58:46.930  SWD\MMDEVAPI\{...} 구성됨   이름 = "1 - Odyssey G80SH"
20:58:48.185  제거                        ← 1.3초 만에
20:59:46.097  제거
```

DP 오디오 엔드포인트는 **EDID 의 CTA-861 확장 블록**에서 파생된다.
→ **모니터가 EDID 확장 블록을 안정적으로 내주지 못한다는 직접 증거**이며,
   소리와 1010 반복이 같은 원인임을 보여준다.

보강 증거: 드라이버 재설치 중 생성된 devnode 의 EDID 가 **128바이트**였다
(정상 384바이트 = base 128 + 확장 256). 확장 블록을 못 읽은 것이다.

### 12-4. EDID 프로파일 이중화의 실체 — 보고서 8항 정정

기존 보고서 8항은 "대기 상태에서 제품 코드가 `7B0B`/`7B11`로 바뀐다"고 봤다. **정정한다.**

```
FreeSync ON    SAM 0x7B0C
FreeSync OFF   SAM 0x7B0B     ← OSD 스위치 하나로 재현 확인
```

스위치는 대기 상태가 아니라 **VRR(FreeSync) 상태**다. 그리고 절전 중 폭풍에서 두 가지가
모두 관측된다:

```
프로파일 간 교대   21:08:41 SAM7B0B → 21:09:13 SAM7B0C → 21:09:40 SAM7B0B
프로파일 내 반복   20:53~20:58  SAM7B0B 만 반복 제거 (FreeSync OFF 고정)
```

→ **제품 코드 전환만이 원인은 아니다.** 어느 프로파일에 고정해도 같은 주기로 제거된다.
   이 항목은 제출 문서에 쓸 때 기존 8항 서술을 반드시 고쳐야 한다.
