## 1. 증상

화면이 절전(화면 꺼짐) 상태에 있는 동안, **약 40~50초 주기로 모니터 장치가 제거**된다.

Windows 이벤트:
`Microsoft-Windows-Kernel-PnP/Device Management` **이벤트 ID 1010**
("버스에 누락된 것으로 보고된 장치 ... 이(가) 제거되었습니다")

동반 증상
- 모니터 오디오 엔드포인트가 같은 주기로 생성/제거 → 연결음·해제음 반복
- 절전 복귀 시 창 배치·크기 흐트러짐

## 3. 발생 조건

### 3-1. 화면 절전 중에만 발생한다

Windows 의 화면 전원 전환 기록(`Kernel-Power` 이벤트 **566**)과 대조하면,
1010 폭풍은 **화면이 꺼져 있는 구간과 정확히 겹친다.** 화면이 켜져 있는 동안에는
거의 발생하지 않는다.

### 3-2. 화면을 끄는 방식과는 무관하다

```
자연 절전 (전원 정책 타임아웃)   → 47초 뒤 폭풍 시작
강제 끄기 (SC_MONITORPOWER)      → 339초까지 0건
자연 절전 (같은 경로 재시도)     → 560초까지 0건
```

끄는 **동작**이 방아쇠가 아니라, 절전에 들어가기 **전의 상태**에 좌우된다.
화면을 껐을 때 첫 발생까지의 지연도 47초에서 1,936초까지 크게 흔들린다.

### 3-3. 재부팅으로 해결되지 않는다

재부팅을 여러 차례 넘겨 재발했다. 9월 20일에도 14:31 재부팅 직후 첫 절전에서
바로 재발했다.

### 4-1. 케이블 교체 (2026-09-20)

같은 PC 에서 **다른 삼성 모니터(G50F)가 13일간 문제없이 사용하던 DP 케이블**로 교체했다.

```
17:41:15  케이블 교체
17:45:13  G80SH 정상 부착.  3840x2160 @240Hz — 네이티브 그대로
17:47:28  화면 꺼짐
17:48:48  첫 1010   ← 81초 만에 재발
          이후 61.4초 / 43.0초 간격으로 반복
```

같은 날 한 시간 전, 원래 케이블로 잰 값과 대조:

| 케이블 | 첫 발생까지 | 시간당 | 주기 |
|---|---|---|---|
| 원래 G80SH 케이블 | 33초 | 147.9 | 37.6~52.6초 |
| G50F 가 쓰던 케이블 | 81초 | 93 | 43.0~61.4초 |

**주기와 이벤트 순서가 구별되지 않는다.**
교체한 케이블로 3840x2160 240Hz 가 그대로 서므로 케이블 성능 문제도 아니다.

### 4-2. DisplayPort DSC 끄기 (2026-09-20)

모니터 OSD 의 **시스템 > DisplayPort DSC** 를 [끄기]로 바꿔 시험했다.

```
19:23     DSC [끄기] 로 전환.  3840x2160 @240Hz 유지됨
19:26:46  화면 꺼짐
19:27:22  첫 장치 제거   ← 36초 만에 재발
19:28:27  65.6초 뒤
19:29:23  54.9초 뒤
```

같은 저녁, 20분 전 DSC [사용] 상태에서 잰 값과 대조:

| DSC | 첫 발생까지 | 시간당 | 주기 |
|---|---|---|---|
| 사용 | 186초 | 약 90 | 40~50초 |
| **끄기** | **36초** | **122.6** | 54.9~65.6초 |

**끈 쪽이 오히려 더 빨리, 더 자주 발생했다.**

이 시험에서 확인된 부수 사실:

- **DSC 를 꺼도 3840x2160 240Hz 가 정상 표시된다.** DisplayPort 2.1 대역폭으로
  압축 없이 이 모드가 서므로, **모니터와 PC 사이의 링크 협상 자체는 정상**이라는 뜻이다.
- **DSC 설정을 바꿔도 EDID 제품 코드는 변하지 않는다**(`SAM7B0C` 유지).
  FreeSync 를 끌 때 제품 코드가 `SAM7B0B` 로 바뀌는 것과 대비된다.

→ **영상 링크는 멀쩡한데, 절전 구간에서 모니터 정보(EDID)만 안정적으로 읽히지 않는다.**

### 4-3. DisplayPort 버전을 1.1 까지 낮춤 (2026-09-20)

링크 구성을 최대한 다르게 만든 시험이다. OSD **시스템 > DisplayPort 버전**을 **1.1** 로
낮추면 다음이 한꺼번에 바뀐다.

```
링크 레이트    DisplayPort 2.1  →  1.1
주사율         3840x2160 240Hz  →  3840x2160 30Hz
DSC            사용 안 함 (이미 끈 상태)
FreeSync       자동 비활성 (설명서 47쪽: "DP 버전이 1.1인 경우 FreeSync 비활성")
EDID 제품코드  0x7B0C  →  0x7B11        ← 모니터가 다른 EDID 를 내보낸다
```

결과:

```
19:33:16  화면 꺼짐
19:33:47  첫 장치 제거   ← 32초 만에 재발
19:34:51  63.5초 뒤
19:35:37  45.7초 뒤
```

### 4-4. 같은 저녁 30분 안에 세 구성을 연속으로 측정했다

| 구성 | EDID | 첫 발생까지 | 시간당 | 주기 |
|---|---|---|---|---|
| DP 2.1 / DSC 사용 / 240Hz | `0x7B0C` | 186초 | 약 90 | 40~50초 |
| DP 2.1 / DSC 끄기 / 240Hz | `0x7B0C` | 36초 | 122.6 | 54.9~65.6초 |
| **DP 1.1 / DSC 끄기 / 30Hz** | **`0x7B11`** | **32초** | **125.0** | 45.7~63.5초 |

**세 구성이 서로 구별되지 않는다.** 반복 주기도, 이벤트 순서도, 발생률도 같다.

**모니터가 어떤 EDID 를 내보내든, 링크를 어떤 속도로 세우든 동일하게 발생합니다.**
PC 와 모니터 사이의 전송 구성은 원인이 아닙니다.

## 5. 커널 추적(ETW) 결과 — 재열거를 개시하는 주체

Windows 커널 추적 원본 **6건**을 확보했다. 각 1010 직전 구간의 이벤트 순서다.

### 5-1. 폭풍 구간

```
-38 ~ -62ms   Kernel-PnP 220   Begin querying bus relations
                               for device PCI\VEN_1002&DEV_7550...   ← 그래픽카드
        0ms   Kernel-PnP 222   End querying bus relations
        0ms   Kernel-PnP 1010  DISPLAY\SAM7B0C\... 제거
      +0.2s   Kernel-PnP 1010  DISPLAY\Default_Monitor\... 제거   ← EDID 읽기 실패
```

**`220` 보다 앞선 모니터 쪽 신호(DxgKrnl 10011)가 단 한 건도 없다.**

### 5-2. 정상 전환 구간 (대조군)

```
-96 ~ -73ms   DxgKrnl 10011 (StatusChangeNotify)   20여 건   ← 모니터 쪽 신호가 먼저
      -24ms   Kernel-PnP 220
        0ms   Kernel-PnP 1010
```

정상적으로 화면을 켜고 끌 때는 **모니터 쪽 신호가 먼저 온다.** 폭풍 구간은 정반대다.

### 5-3. 해석

모니터가 연결을 끊어 알린 것이 아니라, **그래픽 드라이버가 스스로 "자식 장치 목록을
다시 확인하겠다"고 나서고 그 결과 모니터가 사라진 것으로 판단**하고 있다.

그 계기는 EDID 다. 모니터가 절전 중 자신의 정보를 안정적으로 내보내지 못하고 있으며,
그 직접 증거가 `Default_Monitor` **1,339건**(EDID 를 전혀 읽지 못한 상태)이다.

### 5-4. 드라이버 일반의 문제가 아니다

- 이 드라이버는 **2026-08-17 설치**되어 한 달간 G50F 를 문제없이 다뤘다
- **09-08 에 바뀐 것은 이 모니터가 연결된 것 하나뿐**이다
- 드라이버를 완전히 지우고 다시 깔아도 동일하게 재현된다

즉 드라이버의 일반적 결함이 아니라 **이 드라이버가 이 모니터를 다룰 때만** 생기는 일이다.

## 6. EDID 관련 추가 관측

### 6-1. EDID 프로파일이 상태에 따라 바뀐다

```
FreeSync 동작   제품 코드 0x7B0C     ← 평소
FreeSync 해제   제품 코드 0x7B0B     ← OSD 스위치 하나로 재현 확인
저대역폭 링크   제품 코드 0x7B11     ← DisplayPort 1.1 로 낮추면 이 EDID 가 나온다
```

Windows 는 이것을 **서로 다른 세 개의 장치**로 인식한다.

**세 프로파일 전부에서 동일하게 발생하는 것을 확인했다.**

```
0x7B0C   설치 이후 3,204건
0x7B0B   FreeSync 해제로 고정한 상태에서 반복 제거 확인 (09-19)
0x7B11   DisplayPort 1.1 로 고정한 상태에서 반복 제거 확인 (09-20, 위 4-3)
```

→ **프로파일 전환은 원인이 아니다.** 어느 하나에 고정해도 같은 주기로 제거된다.

### 6-2. 확장 블록을 못 읽는 경우가 있다

정상 EDID 는 384바이트(기본 128 + 확장 256)다. 드라이버 재설치 과정에서 생성된
장치 항목의 EDID 가 **128바이트**(확장 블록 없음)로 기록된 사례가 있다.

오디오 정보(Short Audio Descriptor)는 확장 블록에 있으므로, 모니터 오디오 장치가
같은 주기로 생겼다 사라지는 것은 **확장 블록이 읽혔다 안 읽혔다 한다는 직접 증거**다.

### 6-3. 오디오 엔드포인트의 진동이 확장 블록 불안정의 직접 증거다

G80SH 의 EDID 확장 블록은 오디오를 선언하고 있다(헤드폰 단자 출력 경로).

```
CTA-861 확장 블록 (rev 3)
  Basic Audio 지원 플래그  : 예
  Short Audio Descriptor  : LPCM 2채널  32 / 44.1 / 48 kHz
```

이 선언에 따라 Windows 는 `Odyssey G80SH` 라는 오디오 출력 장치를 만든다.
그런데 **이 장치가 모니터 devnode 와 정확히 같은 주기로 생성·제거를 반복한다.**

```
20:58:46.930  오디오 엔드포인트 구성됨
20:58:48.185  제거          ← 1.3초 만에
20:59:46.097  제거
```

오디오 정보는 EDID **확장 블록**에만 있으므로, 이 진동은 곧
**확장 블록이 읽혔다 안 읽혔다 한다는 직접 증거**다.

참고로 이 오디오 장치를 Windows 에서 완전히 사용 중지시킨 상태로도
모니터 제거 현상은 주기·순서까지 동일하게 재현된다(4항 표).
즉 오디오는 원인이 아니라 같은 원인에서 나온 또 하나의 증상이다.

## 7. 설정과 실제 동작의 불일치 — 패널 보호 「자동 연결 해제」

사용설명서 **BN81-29068D-02** 를 대조해 확인한 항목이다.

### 설명서 35쪽 — 이 모델 전용 항목

```
패널 보호 > 자동 연결 해제
  화면 최적화 기능 사용 중에 외부입력을 해제할 수 있습니다.
  • 끄기 / 켜기
  ― S27HG80*S / S32HG80*S 모델만 지원합니다.
```

보유 모델은 **S32HG802S** 로 이 항목이 있는 모델이다.
**현재 값: [끄기]** (2026-09-20 확인)
